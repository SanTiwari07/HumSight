# COOL (Cloud-Optimized OpenCV) evidence sheet

For the **Best Use of COOL** award the competition asks for: the COOL version and AWS instance configuration, a reproducible evaluation method with inputs, baselines and results, and evidence that COOL executes the claimed core workload on the Arm path.

**Status: not run.** No COOL measurement exists yet. This sheet says where each item comes from; fill it in after the run in [DEPLOYMENT.md](DEPLOYMENT.md) §6, and do not copy any number into other documents by hand (embed it from `bench/RESULTS.md`).

## Claimed core workload

Per-patch sub-pixel motion (`phaseCorrelateIterative` over every patch of every frame), spectra, optional stabilisation (`calcOpticalFlowPyrLK`, `findHomography`, `warpPerspective`) and ROI magnification (`pyrDown`/`pyrUp`): the stages timed by `bench/bench.py` as `load+downscale`, `stabilise(warp)`, `patch_shifts(coarse)`, `patch_shifts(fine)`, `spectra`, `magnify(ROI)`, `encode`, plus micro-benchmarks of `GaussianBlur`, `pyrDown`, `pyrUp`, `warpPerspective`, `phaseCorrelate*`, `cvtColor`, `resize`, `Sobel`, `findContours`.

NumPy FFT and Python-level loops are part of several stages; COOL does not accelerate NumPy. The per-stage table shows where COOL helps and where it does not.

## Reproduce

```bash
bash scripts/ec2_setup.sh
python scripts/make_demo_clips.py
INSTANCE_TYPE=c8g.large AMI_ID=<ami> bash scripts/run_bench_ec2.sh
```

Harness sanity check (done on a laptop): two identical stock environments compared with `bench.py --compare` gave about 1.00× per stage, so speed-ups of a few percent are noise.
